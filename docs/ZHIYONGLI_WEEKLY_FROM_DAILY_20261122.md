# 五日日评来源的新版周评分

本次已确认范围为 2026 年 11 月 16—20 日全部参评用户。先发布各日日评，再根据五日已核任务和原文综合形成周评。日总分不参与周评判断，旧版整周重采重评不接入本链路。

- 规则与表现档沿用 1.6，评审版本 `weekly-from-daily-20261122.1`，汇总版本 `weekly-observed-weighted-20261122.1`。
- 周期键为周一至下周一，评价来源为该工作周全部工作日各自已发布的新版日评，包括无活动和仅观察状态。单日最多五个完整任务，不另抽周任务，不为了凑数量补材料。
- 本人行为、原文、时间与工作流归属复用已核日评，不用摘要或日分替代。按分项交付相关完整任务原文，综合判断一次；跨日同一任务结合进展理解，重复决定不重复奖励。跨日重复同一用户记录拦截待查，不静默重复计分。
- 不计分项继续保留未知或不适用，不补零、不补70。维度分按原分项规则精算，周总分按已观察维度的原权重归一；P20、M35、J30、E15。没有观察的维度不进入分母。周分不生成月评级。
- 四项低档归责事实、逐字引文、唯一行为归属和一次有界事实纠正沿用日评门禁。执行错误不得写成人员低分或无活动。
- 每份周评保存五日日评 ID、日期、冻结来源签名、模型请求摘要。导入与发布均验证同人当前已发布来源，任务正文和本人行为须与来源完全一致；来源变化后拒绝继续发布旧候选。
- 周评只证明这些工作日的入选任务表现，不外推全部工作或稳定能力。模型事实检查不等于独立人员能力标定。

接口和页面沿用报告导入、发布、列表与详情接口，新增明确的 `weekly_review` 字段，不复用 `daily_review` 冒充周评。列表隐藏任务正文；个人详情继续仅开放本人已发布报告。生产补评和周评使用既有请求落账与全局预算，恢复时重放事前冻结导入包。
