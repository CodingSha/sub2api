## 已修复问题

| 问题 | 最小处理与保留边界 |
| --- | --- |
| 阅读已收到响应，但非空片段缺少事实依据等已知格式错误使任务直接停住 | 原请求后最多两次修正；反馈只带错误和原响应摘要签名，重新核对整页。各次独立回执，成功页与共享缓存可复用，预算暂停后续跑。不把签名、账簿、截断、拒绝或未知结果当作格式修正；达到上限仍保留待核。 |
| 复查把引用中的逗号改为句号，完整重写复查仍修不对 | 已定位的错误引文只请求 `event`、`quote`，程序仅替换对应槽位。分项结论、本人动作、理由、异议及其他引用保留，连续逐字校验不放宽。最多两次修正，原回执和错误清单进入凭据链。 |
| 同一次纠偏被包装成调整执行、避免无效工作，重复支持 M3/E2 | 评分与复查同时明确主归边界；共用或包含引文的分项对进入核查。同一共引行为被复查双重支持时不能通过。不同判定点可共引，不按引文次数扣分。 |
| 个人报告因依据展示限制而没有判定说明 | 明确提示该说明未在个人报告中展示、可联系管理员核对；不补造理由，不泄露受限原文，不改分数。 |
| 关联状态文字和展开内容不清楚 | 改为“关联其他分项”，展开说明仅作关联、不单独计分。 |
| 任务登记期间仍能修改周期或人员 | 登记请求进行时锁定周期、日期、人员检索和取消已选人员，沿用现有按钮与表单样式。 |

规则手册第五节明确独立判定点与重复计分边界，第九节说明真实评审、发布及执行状态，移除内部模型接入、运维和开发验收说明。用户端、管理员端与下载内容均由 `RulesView.vue` 导入同一份 [1.6 手册](ZHIYONGLI_SCORING_RULES_V1_6.md)。说明更新不自动重评历史报告。
