# 智用力临时容器收尾

2026年11月26日已归档并删除493个已退出的智用力一次性评审容器。清理前后按容器ID核对，其余83个容器均保留；AIHub应用镜像未替换，健康状态正常。其他项目的历史容器和重启问题不属于本次清理范围。

## 根因与修复

历史评审容器未启用自动删除，退出后继续保留。后续版本虽已使用`--rm`，旧容器一直没有定向收尾；部分脚本还假定旧容器对象必须存在，阻碍历史资源清理。

- 当前版本的启动器保存在`deploy/zhiyongli-release-20261126/`。一次性任务使用`--rm`，并明确设置`com.apsat.zhiyongli.owner=zhiyongli`和`com.apsat.zhiyongli.role=ephemeral`；日志与评分回执保留在主机目录。
- 常驻Worker在Compose中标为`persistent`。退出的常驻Worker不会按临时任务清理。
- `deploy/zhiyongli_containers.py`默认只盘点；只有`--apply`才删除。历史容器须根据实际镜像确认属于智用力，不能只按容器名字判断。
- 仅处理已退出且超过10分钟、没有常驻重启策略的评审容器。先压缩保存日志并校验，再保存选定元数据，最后重新检查状态，按不可变ID执行`docker rm`。不使用`--force`、`-v`或全局prune；不删除镜像、卷、状态目录、评分依据或请求账簿。
- 归档失败、状态变化、其他归属或常驻标签均保留容器。归档不保存`Config.Env`和完整命令参数，文件仅供主机管理员访问。

## 安装与验收

在生产部署目录执行：

```sh
sudo bash install-zhiyongli-cleanup.sh
```

脚本只安装独立的systemd收尾定时器，不重启Docker、应用或数据库。主机发布脚本的`build`阶段也会安装该定时器；迁移主机时必须将这一步纳入发布检查。

定时器`zhiyongli-container-cleanup.timer`开机后启用，每次收尾结束10分钟后再次运行。只处理上述范围，异常记录于systemd和私有归档中。

本次已通过10项边界测试；生产分别验证成功退出和失败退出后自动删除，并验证旧式未自动删除容器可以被定向收尾。测试容器使用`--network none`，未发送评分模型请求。

收尾服务手动执行返回`Result=success`、`ExecMainStatus=0`，定时器已启用并产生下一次运行时间。确认没有构建任务后，已停止闲置的智用力专用BuildKit；镜像和构建缓存保留，其他项目服务没有停止。

生产原始清理回执：`/data/zhiyongli/maintenance/containers/1795697248522070/result.json`。相关日志、容器元数据、删除前ID清单和核验记录均保留于同一maintenance根目录，不提交Git。

不要恢复使用历史临时启动命令。复用冻结的发布脚本前仍须核对日期、镜像、来源与预算授权；本记录不授权重新评分。
