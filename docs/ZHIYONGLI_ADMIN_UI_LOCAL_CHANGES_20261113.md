## 实现行为

- 评审列表由服务端对全部任务排序后分页：持有Worker任务会话锁且state为running的排前，其后为遗留running、需关注任务、排队、完成和无活动。同优先级按ID倒序。接口增加`active`，只表示Worker持有执行锁，不代表模型此刻在生成token，也不保证Worker未挂起；页面不得把它描述为模型实时负载。无锁running显示“等待续评”，不播放执行动画。
- 增加状态与账户邮箱筛选，查询在后端执行、返回过滤后总数。状态或查询变化回第一页；每5秒轮询保留已应用条件。
- 状态配色区分等待、执行、待复核、结果不明、失败、生成候选及无活动；实际活动项增加轻量移动高光，减少动态效果偏好下取消移动。
- 周期列分配更宽空间，工作日详情改为标签/内容对齐布局；日期可逐个完整换行，时区只展示一次，保留所有截止日期及封口信息。
- 列表和详情Tooltip共用`ScoreExplanation.vue`；后端读取时增加结构化说明、合并缺维原因。仅当该维度三项均为no_opportunity时表达“未观察到可评分行为”，其余表达为缺少完整可评依据，并保留来源未完成、归属/复核和其他资格原因。不改原score_reason或已发布修订；旧接口无新字段时保留原说明作为明确版本兼容。
- 批量发布由管理员显式确认。同一周/月周期最多100份，确认框列出邮箱及有/无总分数量，范围跨分页并受当前账户查询限制。多周期草稿超过100时先取最近周期，其他周期可用新增的周期开始日期筛选。后端校验同周期、ID不重复、修订、最新版本、个人参评范围及现有工作日要求；任一失败整批回滚，重复提交已发布同修订可复用。事务与现有单份发布共用锁和校验，不并发逐份发布，不自动发布，不排除所有缺维报告。
